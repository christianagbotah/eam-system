   861→   861→   861→## 12. INVENTORY STOCK-UP / STOCK-IN ANALYSIS (Critical Finding)
   862→   862→   862→
   863→   863→   863→### How inventory stock gets INCREASED:
   864→   864→   864→
   865→   865→   865→1. **PRIMARY: Purchase Order Receipt** (`/api/purchase-orders/[id]/receive` POST)
   866→   866→   866→   - Creates ReceivingRecord + increments InventoryItem.currentStock + creates StockMovement(type: 'in', reason: 'PO Receipt')
   867→   867→   867→   - This is the standard procurement → receiving → stock-in flow
   868→   868→   868→
   869→   869→   869→2. **SECONDARY: Inventory Adjustment (Gain)** (`/api/inventory/adjustments/[id]` PUT with action: 'approve', type: 'gain')
   870→   870→   870→   - Requires approval workflow (pending → approved)
   871→   871→   871→   - Used for stock corrections, found stock, cycle count adjustments
   872→   872→   872→
   873→   873→   873→3. **TERTIARY: Reconciliation Return** (`/api/repairs/material-requests/reconcile` POST)
   874→   874→   874→   - Returns unused materials from repair work orders back to inventory
   875→   875→   875→   - Increments currentStock + creates StockMovement
   876→   876→   876→
   877→   877→   877→4. **QUATERNARY: Spare Part Return to Store** (`/api/repairs/spare-part-returns/[id]` PUT)
   878→   878→   878→   - Returns refurbished/reusable spare parts to inventory store
   879→   879→   879→
   880→   880→   880→5. **INITIAL: Item Creation** (`/api/inventory` POST)
   881→   881→   881→   - Sets initial currentStock at creation time
   882→   882→   882→
   883→   883→   883→### How inventory stock gets DECREASED:
   884→   884→   884→
   885→   885→   885→1. **Repair Material Issue** (`/api/repairs/material-requests/[id]` PUT with status transition to 'issued')
   886→   886→   886→   - Deducts from currentStock when materials are issued for repair
   887→   887→   887→
   888→   888→   888→2. **Inventory Adjustment (Loss)** (`/api/inventory/adjustments/[id]` PUT with action: 'approve', type: 'loss')
   889→   889→   889→   - Stock write-off, damage, shrinkage
   890→   890→   890→
   891→   891→   891→3. **Inventory Transfer Out** (temporary — same item gets stock back when transfer completes)
   892→   892→   892→
   893→   893→   893→### KEY FINDING: No direct 'stock-up' endpoint
   894→   894→   894→- The `PUT /api/inventory/[id]` deliberately excludes `currentStock` from allowedFields
   895→   895→   895→- Stock changes MUST go through audited workflows (PO receiving, adjustments, reconciliation)
   896→   896→   896→- All stock movements are tracked in the `StockMovement` table
   897→   897→   897→
   898→   898→   898→### MISSING: No 'quick stock-in' or 'direct stock addition' endpoint
   899→   899→   899→- There is no way to quickly add stock without creating a PO or an adjustment
   900→   900→   900→- For urgent situations, users must either: (a) create a PO and receive against it, or (b) create an inventory adjustment (gain type)
   901→   901→   901→- A dedicated 'stock-in' or 'receiving' endpoint that doesn't require a PO could be useful for walk-in donations, inter-company transfers, or emergency stock additions
   902→   902→   902→
