   383→Asset (machine) -> 1:N ComponentRegistry (via assetId FK)

   385→ComponentRegistry -> 1:N ComponentToolRequirement -> Tool (tools needed)
   386→Asset -> 1:N BillOfMaterial (as parent) -> BomRevision -> BomRevisionItem (links to Component + InventoryItem)
   387→Asset -> 1:1 DigitalTwin -> DigitalTwinScene -> AssetModel
   388→Asset -> 1:N AssetModel -> AssetMeshBinding -> Asset (component assets)
   389→
   390→### 2.2 Machines/Components to Work Orders and Repairs
   391→
   392→Asset <-> WorkOrder: **BROKEN** (plain String assetId, no FK relation)
   393→ComponentRegistry <-> WorkOrder: via WorkOrderComponent join table (OK)

   395→WorkOrder -> RepairMaterialRequest: 1:N (OK)
   396→WorkOrder -> RepairToolRequest: 1:N (OK)
   397→WorkOrder -> WorkOrderDowntime: 1:N (OK)
   398→WorkOrder -> RepairCompletion: 1:1 (OK)
   399→WorkOrder -> SparePartReturn: 1:N (OK)
   400→PmSchedule -> WorkOrder: 1:N auto-generated (OK)
   401→MaintenanceRequest -> WorkOrder: 1:1 (OK)
   402→
   403→### 2.3 Inventory to Repairs/Work Orders
   404→
   405→InventoryItem -> RepairMaterialRequest: 1:N via itemId FK (OK)

   407→InventoryItem -> PurchaseOrderItem -> PurchaseOrder -> ReceivingRecord (OK)

   423→## 3. GAP ANALYSIS
   424→
   425→### 3.1 CRITICAL: Broken / Missing Prisma Relations
   426→
   427→Over 60 plain-String ID fields across 30+ models lack @relation decorators:
   428→
   429→- WorkOrder.assetId -> Asset: **CRITICAL** - core business link broken
   430→- WorkOrder.departmentId -> Department: **CRITICAL**
   431→- WorkOrderMaterial.itemId -> InventoryItem: **HIGH**
   432→- SpatialNode.assets declared but Asset has no spatialNodeId FK: **CRITICAL - BROKEN RELATION**

   861→## 12. INVENTORY STOCK-UP / STOCK-IN ANALYSIS (Critical Finding)
   862→
   863→### How inventory stock gets INCREASED:
   864→
   865→1. **PRIMARY: Purchase Order Receipt** (`/api/purchase-orders/[id]/receive` POST)
   866→   - Creates ReceivingRecord + increments InventoryItem.currentStock + creates StockMovement(type: 'in', reason: 'PO Receipt')
   867→   - This is the standard procurement → receiving → stock-in flow
   868→
   869→2. **SECONDARY: Inventory Adjustment (Gain)** (`/api/inventory/adjustments/[id]` PUT with action: 'approve', type: 'gain')
   870→   - Requires approval workflow (pending → approved)
   871→   - Used for stock corrections, found stock, cycle count adjustments
   872→
   873→3. **TERTIARY: Reconciliation Return** (`/api/repairs/material-requests/reconcile` POST)
   874→   - Returns unused materials from repair work orders back to inventory
   875→   - Increments currentStock + creates StockMovement
   876→
   877→4. **QUATERNARY: Spare Part Return to Store** (`/api/repairs/spare-part-returns/[id]` PUT)
   878→   - Returns refurbished/reusable spare parts to inventory store
   879→
   880→5. **INITIAL: Item Creation** (`/api/inventory` POST)
   881→   - Sets initial currentStock at creation time
   882→
   883→### How inventory stock gets DECREASED:
   884→
   885→1. **Repair Material Issue** (`/api/repairs/material-requests/[id]` PUT with status transition to 'issued')
   886→   - Deducts from currentStock when materials are issued for repair
   887→
   888→2. **Inventory Adjustment (Loss)** (`/api/inventory/adjustments/[id]` PUT with action: 'approve', type: 'loss')
   889→   - Stock write-off, damage, shrinkage
   890→
   891→3. **Inventory Transfer Out** (temporary — same item gets stock back when transfer completes)
   892→
   893→### KEY FINDING: No direct 'stock-up' endpoint
   894→- The `PUT /api/inventory/[id]` deliberately excludes `currentStock` from allowedFields
   895→- Stock changes MUST go through audited workflows (PO receiving, adjustments, reconciliation)
   896→- All stock movements are tracked in the `StockMovement` table
   897→
   898→### MISSING: No 'quick stock-in' or 'direct stock addition' endpoint
   899→- There is no way to quickly add stock without creating a PO or an adjustment
   900→- For urgent situations, users must either: (a) create a PO and receive against it, or (b) create an inventory adjustment (gain type)
   901→- A dedicated 'stock-in' or 'receiving' endpoint that doesn't require a PO could be useful for walk-in donations, inter-company transfers, or emergency stock additions
